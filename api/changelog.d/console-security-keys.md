### Security: platform console security keys and passkeys

- Platform administrators can register security keys and passkeys (WebAuthn, user verification required) and use them to sign in to the console and to confirm protected actions; the console offers them before the authenticator-app code. The relying party is the console's own origin (`ADMIN_PUBLIC_URL`, default the origin of `APP_URL`), so an assertion from the tenant site or a look-alike domain is refused.
- Ten one-time recovery codes per administrator, shown once and regenerated with a step-up.
- New console policy "require security keys" (System > Security, super admin with step-up). It turns on only when the administrator turning it on has at least two keys and recovery codes; other administrators keep signing in but reach only the enrollment page until they comply, the last two keys cannot be removed, and the authenticator-app code is refused for an administrator who holds a key (break-glass administrators keep it). Reset credentials also removes keys and recovery codes.
- Upgrade note: additive migration (`admin_webauthn_credentials`, `admin_recovery_codes`, `admin_webauthn_ceremonies`). Set `ADMIN_PUBLIC_URL` to the console site (`https://<OPENCTEM_ADMIN_HOST>` or `https://<host>:8444`) when the console has its own site; changing it later makes registered keys unusable.
