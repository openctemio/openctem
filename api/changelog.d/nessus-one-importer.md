### Removed: the API's own .nessus parser and its two upload routes

- `POST /api/v1/assets/import/nessus` (hosts only, no caller) and `POST /api/v1/assets/import/nessus-findings` are removed, with the parser and converter behind them. A `.nessus` export is uploaded to `POST /api/v1/findings/import`, which converts it with the shared ctis importer, like every other format. Settings → Vulnerability scanners now uses that route (with `min_severity=low`, as before).
- What the import keeps is equal or richer: every CVSS version with its vector, VPR, EPSS, typed vulnerability ids, CWEs, advisories, KEV and exploit maturity, one finding per compliance check (they used to collapse into one per plugin), host identity hints (FQDN, NetBIOS, MACs, OS CPE). Findings stored by earlier uploads keep their identity (host, CVE or plugin, port) and are updated, not duplicated.
- The scan policy is never read, and plugin output and compliance values are redacted of accounts, passwords, tokens and community strings; the removed converter copied plugin output as is.
- **Upgrade note:** a script that posted raw XML to `/assets/import/nessus-findings` posts the file as multipart part `file` to `/findings/import` (one file up to 100 MiB, or a ZIP of several). `session_id` and `tool` are gone: the import record is the producer, the tool is `nessus`. Neither route ever auto-resolved findings.
