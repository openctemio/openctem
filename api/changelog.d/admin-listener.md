### Added: the platform console API can have its own listener

- New `ADMIN_LISTEN_ADDR` (a loopback or private IP and port, e.g. `10.0.0.5:8081`; any other address, including every interface, needs `ADMIN_LISTEN_ALLOW_ALL_INTERFACES=true`): the console API (`/api/v1/admin`) is served only on that listener, and the main listener answers 404 for it; the admin listener answers 404 for every tenant, sensor or public route (`/health` excepted). The console is recognised however the path is written (`//`, `.`/`..` segments, a trailing slash, percent-encoding), so neither listener can be crossed by spelling the path differently. The listener is plain HTTP for the private network between the web console and the API; put TLS in front of it where that network is not trusted. Unset (the default), nothing changes.
- **Upgrade note:** set it only together with routing the console to it (the gateway's admin site and the web console's `ADMIN_API_URL`, shipped with the deployment kits); otherwise the console becomes unreachable.
