### Security: only network scope entries authorize active probes

- A scope entry of a type with no matcher (certificate, container, database, mobile app, cloud resource, network) was compared as wildcard text, so the pattern `*` covered every host and address for active probes, past the public-suffix and CIDR-size guardrails. A URL, API or website entry could carry a wildcard host and do the same. Only domain, address, range, CIDR, host, URL (with a concrete host) and repository entries authorize probes now, and every other type covers nothing. The deny list, exclusions and guardrails are unchanged and still run first.
- The API refuses `*` in every entry type that has no wildcard matcher (`SCOPE_WILDCARD_NOT_ALLOWED`) and refuses new entries of the types that name no network location (`SCOPE_TARGET_TYPE_RETIRED`). URL entries need `http://` or `https://` and a concrete host. Host entries get the public-suffix, deny-list and size checks.
- Upgrade note: migration `scope_wildcard_entries` takes existing wildcard entries of those types out of effect (active becomes inactive, pending becomes rejected) and writes one audit event per entry in its own tenant. Probes that relied on such an entry stop being authorized until a domain, address or network entry covers them. The migration changes data only; the previous API keeps working.
