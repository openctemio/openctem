### Behaviour change: confirming an asset also adds it to scope

- When a person confirms assets as the organization's (the review queue or an asset's Ownership section), the exact scope entry of each confirmed name, address, network, service or application that no entry covers is added, so scans can reach it without a second step. Only in the Off and On scan approval modes, and only while the new scope setting `confirm_adds_to_scope` is on (the default; `PUT /scope/settings`). Hosts, repositories, cloud resources, private addresses and internal names get no entry; automated decisions never add one. Entries go through the usual path (guardrails, the job signer's ledger, audit per entry, one notice to the administrators); without a recent re-authentication nothing is added and the response lists the pending entries (`scope.step_up_required`, `scope.pending`). RFC-054 §14.5.
