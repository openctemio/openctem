### Added: AI use cases in Settings, one shared AI badge and AI suggestions on the finding page

- Settings > AI has a Use cases section: per use case (triage, remediation steps, summary) the mode (off, suggest, auto-apply), the most sensitive data class sent (public, internal, restricted) and the minimum confidence for auto-apply (0.50 to 0.99). It says when a use case is not in effect because AI triage is off, explains an automatic fall back from auto-apply to suggest with a way to turn it back on, and states the fixed rules: auto-apply only adds information, anything that lowers risk becomes an approval request, severity changes always wait for a person. Turning auto-apply on or raising the data class asks for confirmation and a recent sign-in.
- The finding page lists the finding's open and applied AI suggestions grouped by kind, with the direction the platform computed, confidence, evidence and state; Apply, Dismiss and Undo ask first, a false-positive verdict needs a closure reason, and "Why?" shows what the run sent and withheld, the model, the prompt template and its cost. Model output is shown as plain text, never as markdown or HTML, and long text is cut with Show more.
- Every AI-produced item (suggestions, AI triage results, AI-proposed approval requests) carries one shared AI badge that names its source: AI triage, an AI analyst, or an AI application connected over MCP. A gate test fails when an AI suggestion component does not use it.
- Settings > AI has a Data masking section: switches per class of value masked in internal data (hosts, IP addresses, e-mail addresses, user names, URL ids and parameters, organization names, ticket ids), the subdomain label switch and extra terms (up to 200, 3 to 128 characters). Secrets are shown as always masked and locked, restricted data as always fully masked. A preview shows, for one finding id, the masked text the model would get (plain text), the placeholders with their class only, and the fields sent and withheld, with a note on what masking does not hide. Saving needs a recent sign-in; a change that masks less asks first.
- The console shows nothing of this until the API offers the AI governance and masking routes.
