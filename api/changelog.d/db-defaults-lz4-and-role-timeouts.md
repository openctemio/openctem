### Changed: large values compress with lz4, and the API's database role has a statement and an idle-in-transaction timeout

- The bundled Postgres starts with `default_toast_compression=lz4` (`PG_TOAST_COMPRESSION` overrides it), and the new migration sets lz4 on eleven large columns (finding description, scanner output and source extra, command payload, result and logs, ingest report headers and job payloads, sensor manifests, finding evidence, AI triage raw responses). Existing values are not rewritten; a server without lz4 is left alone.
- `least-privilege-roles.sql` sets `statement_timeout = 30s` and `idle_in_transaction_session_timeout = 60s` on the app role (variables `app_statement_timeout` and `app_idle_in_transaction_timeout`, `0` turns one off). The migrator has no limit.
- **Upgrade note:** re-run the roles script (the compose `db-roles` job does it on every `up`) and restart the API for the limits to apply. A query that ran longer than 30 s is now cancelled with SQLSTATE 57014; if one is legitimate, raise the limit for that statement with `SET LOCAL statement_timeout` or raise `app_statement_timeout`.
