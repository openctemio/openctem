### Fixed: a scan closes what it no longer finds on the hosts it really covered

- Coverage auto-resolve decides coverage per target when the command result says how every target ended (`target_outcomes`). One host that stopped answering, sat behind an edge block, hit the rate floor or timed out no longer makes the whole run prove nothing: the other targets, whose outcome is `done` and whose host no gap, unreached or refused entry names, count as covered. A target without an outcome, a cut-short gap list or unreadable metadata counts as not covered.
- The covered assets now include the assets with open findings of the same tool last seen by a command aimed at a covered target, also when this run reported nothing there. Before, only assets the run's report named were candidates, so a host where the scan found nothing could never close its old findings.
- Every other condition is unchanged: the coverage mode (`INGEST_COVERAGE_AUTO_RESOLVE`, default `dry_run`), same tool and scan profile as the last sighting, the template release, the blinding guard, command-bound assets, secrets marked not observed, protected sources. A run from an older sensor without per-target outcomes keeps today's behaviour (full and clean, or nothing).
