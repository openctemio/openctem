### Added: retest a finding with its own tool's retest handler

- A finding whose tool has a retest handler on a tenant sensor (the sensor reports `retest:<tool>`; sdk-go tool contract retest) is retested by one `retest` command to that tool. Its verdict for the finding settles the retest: `still_present` reopens a resolved finding as a regression, `fixed` resolves it (`retest_verified`), and `unverifiable`, a missing or foreign verdict, or a failed command leaves it unchanged (unknown). Retest now, proof of fix and auto-retest use it whenever such a sensor is online; nuclei findings fall back to the template re-run plus reachability probe otherwise.
- Findings of any tool with a rule id can now be retested when their tool's retest handler is online. Eligibility, limits, gates, activities (now with `method`), SLA restart and announcements are unchanged.
- The `retest` command passes the same active-probe gate as validate commands, names the tool as `scanner` and lists plain addresses, so the claim-time tool predicate and the sensor's local-policy admission apply. Sensors report `retest:<tool>` only for a known tool. Migration 001135 adds the `retest` command type (no long lock on `commands`).
