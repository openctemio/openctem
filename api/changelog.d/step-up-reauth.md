### Security: sensitive actions need a recent sign-in or step-up re-authentication

- New `POST /api/v1/auth/step-up` (and `GET` for the state): the signed-in user proves their identity again (a current authenticator code when two-factor authentication is on, otherwise the password) and the current session may perform sensitive actions for 10 minutes. The window is stored on the session (migration 001110, `sessions.step_up_at`), belongs to that session only, and moves only with a new proof. Wrong or replayed proofs count towards the account lockout, are rate limited per IP and are audited (`auth.step_up_failed`); success is audited (`auth.step_up`).
- These routes now answer `403 STEP_UP_REQUIRED` unless the session signed in or stepped up within 10 minutes: create and delete API keys, create a SCIM token, organization security settings, approving an SSO change, deleting the organization, resetting a member's two-factor authentication, offboarding and erasing a member, creating a CI gate override, rebaselining the audit chain.
- **Behaviour change:** scripts that call those routes with an access token must call `POST /api/v1/auth/step-up` first (or act within 10 minutes of signing in). SSO accounts without an authenticator sign in again. Requests without a user session (API keys, external OIDC provider tokens) get `403 STEP_UP_UNAVAILABLE` on them.
