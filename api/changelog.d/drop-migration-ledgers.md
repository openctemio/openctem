### Removed: rollback ledgers of finished data migrations (migration 001481)

- Migration 001481 drops twelve tables that past data migrations kept only so their own down migrations could put rows back: `access_control_removed_archive`, `asset_type_input_map`, `asset_type_legacy_codes`, `asset_types_legacy_removed`, `asset_type_reclassifications`, `asset_properties_pre_001185`, `easm_ct_rekey_001018`, `granular_permission_backfill`, `technique_applicability_rekey_ledger`, `technique_applicability_subtype_moves`, `legacy_templates_backup_001322` and `legacy_template_steps_backup_001322`, plus the function `asset_type_normalise_batch`. Nothing in the application reads them.
- A new unit test refuses a migration that creates a backup, ledger or archive table unless a later migration drops it or an allowlist entry with an expiry date covers it, so such tables do not pile up again.
- **Upgrade note:** one step, no code change needed. The rows are rollback data only; they are not restored by the down migration (it recreates the tables empty), so a down migration of 001322, 001286, 001185, 001184 or 001179 run afterwards restores nothing. Take the usual pre-upgrade backup if you may need them. Run the migration explicitly; `air` does not run migrations.
