### Security: console identity and trust changes need a fresh authenticator code

- Every platform-console write that changes an identity, a privilege, an organization's trust or a platform setting asks for a fresh authenticator code (step-up), or rides the five-minute step-up window of the same console session: administrators (provision, change, delete, reset, break-glass test, identity-provider unbind, ending a session), the platform identity provider, account support actions on users, organization creation, access-request approval, owners, organization SSO, module grants, scan-approval policies, the audit-chain rebaseline, and the sign-up, e-mail, legal, limits, modules, platform-sensor-proof, content-pack and program-feed settings. A stolen console session alone can no longer add an administrator or swap the console's identity provider. The routine writes left (limits, idle exemption, rejecting a request, announcements, feed sync, AI-client blocks, target mappings, the e-mail test) are listed with their reason, and CI fails on an unclassified console write.
- The API answers `401 ADMIN_STEP_UP_REQUIRED` without a code (header `X-Admin-Step-Up`); the console asks for it and retries. Forms that already asked for a code (`totp_code`) send it in that header as well, so nobody is asked twice.
- Migration 002420 adds `admin_sessions.step_up_at` (nullable, no backfill).
- **Upgrade note:** an administrator who signs in only through the platform identity provider has no console authenticator and gets `403 STEP_UP_UNAVAILABLE` on these actions; keep at least one super admin with a console authenticator (every break-glass account has one).
