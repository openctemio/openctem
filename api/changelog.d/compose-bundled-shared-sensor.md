### Added: compose overlay for a bundled sensor enrolled as a shared sensor

- `api/deploy/docker-compose.sensor.yml` runs a sensor next to the stack that enrolls as a shared sensor of the instance. A one-shot `sensor-enrollment` service registers `SENSOR_INSTANCE_ENROLLMENT_TOKEN` (`bootstrap-admin sensor-token`, valid one hour, single use) after the migrations; the sensor enrolls with it on first start and keeps its identity in the `sensor-data` volume.
- The sensor runs in shared mode (`SENSOR_SHARED_MODE=1`, sandbox and network confinement required, the local policy `./sensor/sensor-policy.yaml` required), with no capability added (`cap_drop: ALL`, no-new-privileges, read-only root) and the sensor release's seccomp profile (`sensor/seccomp.json`: Docker's default plus clone/unshare with namespace flags, for its per-task user, network and mount namespaces). Shared jobs reach only a sensor that advertises `shared.isolation@1`; a sensor image without shared mode enrolls but receives none.
- `setup.sh` writes a generated `SENSOR_INSTANCE_ENROLLMENT_TOKEN` (`octe_` and 49 letters or digits) into a new `.env`, and copies `sensor/sensor-policy.example.yaml` (public targets only) to `sensor/sensor-policy.yaml`.
- **Upgrade note:** the overlay is opt-in. An existing install whose sensor was paired as an organization sensor keeps it; add `SENSOR_INSTANCE_ENROLLMENT_TOKEN` to `.env` (octe_ and 49 letters or digits) only to start the overlay.
