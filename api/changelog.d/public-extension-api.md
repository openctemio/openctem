### Added: public, versioned back-end extension API (`pkg/extension`)

- Anyone can build their own edition against `api/pkg/extension`: one `Register(Extension)` call with the API version it was written for (`APIVersion`, a mismatch stops the start), a grant provider, background controllers, HTTP routes under `/api/v1` (each needs a core permission and a grant key; mounted behind the organization chain, the permission and the grant), migrations in the extension's own schema, and the config keys it reads. What the core hands over (`Deps`) is interfaces only: a scoped `Store` (one transaction per call, no pool), declared settings only (a key the core owns is refused at start), entitlements, read access to the administrators' audit chain for an audit sink, and the environment. `pkg/extension/example` is a complete extension compiled and tested in every core build; `testdata/api.golden` records the exported surface.
- `/api/v1/version` (and `/admin/version`, `openctem-server -version`) reports the build's `edition` (`community` without an extension) and the `extension_api` version.
- An extension that lists the off-box audit stream settings (`ADMIN_AUDIT_SINK*`) takes the stream over; the core's own stream then stays off, so it never runs twice.
