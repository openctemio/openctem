### Security: per-sensor grants, enforced by the platform (RFC-052)

- Every sensor has a grant: job types, zones, tools, capabilities, tier ceiling (T0 passive, T1 active, T2 intrusive), target network (any, public only, none) and CIDR/domain scope, credentials, results without a job (push ingest) and gated remote actions, plus a trust level. The platform checks it on every poll, claim-N and claim by id, on results without a job and on heartbeat actions, whatever the sensor reports and even for a job a person scheduled.
- Trust level **New** caps a sensor at passive (T0) work with no credentials and no push ingest until an administrator promotes it. A paired sensor starts New with the profile chosen at approval (`internal-network-scanner` by default; `easm-external`, `authenticated-scanner`, `collector:<integration>`, `ci-runner`, `endpoint-agent`); a re-paired sensor returns to New.
- `GET /api/v1/sensors/{id}/grant`, `PUT /api/v1/sensors/{id}/grant`, `GET /api/v1/sensors/grant-profiles`, `GET /api/v1/sensors/grant-summaries`. Narrowing and demoting need `sensors:grant:narrow`; widening and promoting need `sensors:grant:widen`, are audited at high severity (`sensor.grant_changed`, with a diff) and notify every administrator. Changes use the grant's version (a stale one answers 409).
- Refusals are audited and on the sensor's timeline: `sensor.claim_refused_grant`, `sensor.credential_refused`, `sensor.push_refused_grant`. A refused claim by id answers like a lost claim (`command-claimed`). Claim by id now also checks the command's required capabilities.
- **Behaviour change:** a sensor created after this release (API key or pairing) starts at trust level New: it gets only passive jobs and its results without a job are refused (item error `push_ingest_not_granted`) until an administrator promotes it and allows push ingest. Sensors that exist at upgrade keep working: they get the broad legacy grant at trust level trusted, which the console flags so it can be narrowed.
- Migration **001099** adds `sensor_grants` (legacy-broad backfill for existing sensors, an insert trigger for the narrow default of new ones) and `sensors.trust_level` (trusted for existing sensors, new for later ones).
