### Added: A CI trust adds the repositories it trusts to scope

- With "Trust and add to scope" (`manage_scope`), a GitHub (github.com, GitHub Enterprise Server) or GitLab (gitlab.com, self-managed) trust adds a linked repository scope entry for each owner (`<host>/<owner>/*`) or repository it trusts. Other providers name their code host per run and do not.
- The entries are created as the person who saves the trust, through the same scope decision as adding them by hand. With scan approval off they are in effect at once; under Strict, an approver's entries wait for their approvals and anyone else's are not added. Administrators are told, as for any widening.
- An equal entry that already exists is linked, never duplicated, and stays the person's. Entries the trust created (origin `ci_trust`) follow the trust: an edit moves them, disabling or deleting the trust retires them, and two trusts on one namespace share one entry until the last goes.
- The first verified pipeline run under a pattern is recorded as evidence (`scope_entries[].seen_*` on the trust, `managed_by[]` on the scope entry). A legacy-audience run never counts. A run never creates an entry; it may only link an existing equal one.
- Opt-in governance: the scope setting `ci_scope_requires_proof` (default off) keeps a trust's new entries inactive until a verified run under them. That run puts an entry into effect only while the organization needs no approvals for it at that moment; if scan approval turned Strict in the meantime, the entry waits for its approvals and administrators are told.
- Security: `manage_scope` needs `attack_surface:scope:write` (403 `MANAGE_SCOPE_FORBIDDEN`). Without it the default is off, and such a caller may rename or narrow a trust, never widen its scope. An entry a trust manages answers 409 `CI_TRUST_MANAGED` to scope edits of its tier, expiry, reason or discovery, and to activate, deactivate and delete; change the trust or add an exclusion. An existing entry a person deletes is recorded on the link (`removed_at`) and is never created again by the trust. Links are tenant-scoped with composite foreign keys.
- Migration `002178_ci_trust_managed_scope` adds `ci_trust_configs.manage_scope` (existing trusts stay off; an administrator turns it on per trust), the origin `ci_trust` and the table `scope_target_ci_trusts`.
