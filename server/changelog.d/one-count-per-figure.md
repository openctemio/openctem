### Fixed: the same count says the same number on every page

- Assets: "All assets" in the sidebar and the Assets tile on Business impact counted every name, including those still waiting for review, while the asset list leaves them out (814 against 615). `GET /assets/stats` now takes the list's `attribution` filter through the list's own field, and both pass the list's default, so each count is the list's total.
- Active findings: the sidebar's findings views counted compliance checks that the list (Vulnerabilities, its default view) and every dashboard leave out (9,368 against 9,359). `GET /findings/quick-views` now counts under a practice view, `?practice=` (default: vulnerabilities; or `all`, or one practice).
- Business units: their asset, finding and critical counts were stored numbers refreshed only when an asset joined or left a unit, so findings opened later never showed. Every reader now gets counts computed when the unit is read, over the dashboard's findings (open, not held, no compliance check, no program-only asset). A unit without assets says "No assets assigned" instead of "No open risk".
- Crown jewels: the tile counts the register's total instead of the rows loaded, and the "Showing the first N of M" notice links to the asset list for the rest.
- Labels where two numbers count different things: "All exposures, any state" on Exposures; "Open external exposures" on Attack surface, whose "All exposures" button no longer shows the external count next to a list of every exposure; "External assets measured" on the posture strip; "Unassigned open findings" (opened in the last 90 days) on the executive summary; "All findings, any status" on Data quality, whose link now opens every state.
- Docs: none (the API reference is generated from the handler annotations, where the new `attribution` and `practice` parameters are documented, and no guide describes these counts)
