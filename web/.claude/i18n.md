# Internationalization (i18n) Guide

> How the web console picks a locale, translates strings and sets text direction.

## Locales

```typescript
// src/lib/i18n.ts
export const supportedLocales = ['en', 'vi'] as const // selectable and detectable
export const defaultLocale = 'en'
export const rtlLocales = new Set(['ar', 'he', 'fa', 'ur']) // direction only
```

- **Shipped catalogs:** English (`en`) and Vietnamese (`vi`), in
  `src/lib/i18n/dictionaries/{en,vi}.json`.
- Add a locale to `supportedLocales` only once its dictionary ships. An RTL
  locale (for example `ar`) is added only after the layout has been checked
  right-to-left; until then no RTL locale is selectable and pages render
  `dir="ltr"`.

## Locale detection

1. `src/proxy.ts` calls `detectLocale()` (`src/lib/middleware/i18n.ts`): the
   `locale` cookie (set by the language switcher,
   `src/components/language-switcher.tsx`), then `Accept-Language`, among
   `supportedLocales`, falling back to `en`.
2. The proxy passes the result as the `x-locale` request header.
3. The root layout (`src/app/layout.tsx`) validates it with
   `isSupportedLocale()`, sets `<html lang={locale} dir={getDirFromLocale(locale)}>`
   and hands `locale` to the providers.

## Translating strings

Client components use the dependency-free translation layer:

```tsx
'use client'
import { useTranslation } from '@/context/i18n-provider'

export function SaveButton() {
  const { t } = useTranslation()
  return <Button>{t('common.save', 'Save')}</Button>
}
```

- `t(key, fallback?, vars?)` resolves the key in the active catalog, then in the
  English catalog, then the `fallback`, then the key itself. A key missing only
  from `vi.json` therefore still renders English text.
- Interpolation uses `{name}`: `t('assets.count', '{count} assets', { count })`.
- Keys are dotted and grouped by area (`nav.group.scoping`, `common.save`, ...).
- Server Components read the locale from `(await headers()).get('x-locale')` and
  use `getDictionary(locale)` + `translate()` from `@/lib/i18n`.

## Adding or changing strings

1. Add the key to `en.json` (source of truth) and, when you can, to `vi.json`.
2. Use `t('your.key', 'English fallback')` in the component.
3. Settings navigation items carry their en/vi labels in
   `src/config/settings-nav.ts`; `settings-nav.test.ts` checks them.
4. `src/lib/__tests__/i18n.test.ts` covers the resolution rules.

Not every screen is translated yet: strings without a key render as written
(English).

## Direction (RTL)

`getDirFromLocale()` returns `rtl` for `ar`, `he`, `fa` and `ur`. The
`DirectionProvider` (`src/context/direction-provider.tsx`) exposes the direction
to components. Use logical Tailwind utilities (`ms-*`, `me-*`, `ps-*`, `pe-*`,
`start-*`, `end-*`, `text-start`) instead of `ml-*`/`mr-*`/`left-*`/`right-*`, so
an RTL locale needs no layout changes when it ships.
